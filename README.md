# Record Plotter

A small Windows program that plots CSV and fixed-width record files. It works out how to
read a file on its own - delimiter, encoding, column widths, header, decimal separator, date
format - and asks the user nothing.

- C++17 and plain Win32, drawn with Direct2D/DirectWrite. No dependencies: one ~400 KB
  `RecordPlot.exe`, no installation.

## Usage

- **OPEN FILE** (Ctrl+O), drag a file onto the window, or run `RecordPlot.exe file.csv`.
- The left panel shows what was detected: format, encoding, decimal separator, header,
  row count.
- **X AXIS**: a timestamp column is chosen automatically; any other column or the row number
  can be picked instead.
- **SERIES**: the columns to draw; the swatch is the line colour.
  - The **LEFT/RIGHT** badge at the end of a row (or ← / →) moves a series to a second Y axis,
    so series of very different size (119 kV beside 0.003 MVAr) stay readable together. The
    coloured bars above the plot show which series belongs to which axis.
  - **Assign axes automatically** (on by default, remembered): when a file opens and whenever
    the selection changes, series are split between the two axes so that the hardest one to
    read fills as much of its axis as possible. If everything is readable on one axis,
    everything stays left. Clicking a badge by hand turns the automatic choice off.
  - Names too long for the row end in "…"; hovering shows the full name.
- Plot:
  - wheel zooms both axes, Shift+wheel time only, Ctrl+wheel values only;
  - drag pans, Ctrl+drag zooms to a box;
  - double-click, Home or **FIT** shows all data;
  - hovering shows the values of the nearest row.
- **SAVE PNG** (Ctrl+S) saves the plot at twice the screen resolution.

Rendering without a window:

```
RecordPlot.exe --render in.csv out.png [width height] [--hover 0.5] [--right 1,3]
```

## Detection

Every plausible layout is tried (`,` `;` tab `|` delimited, whitespace separated, fixed
width). Sample lines are split with each and scored on how consistent the rows are and how
many cells are clean numbers or dates. A wrong layout cuts values in half (`12,5;13,7` split
on the comma gives `5;13`) and loses.

| Case | Handling |
|---|---|
| Encoding | BOM; UTF-16 without BOM; valid UTF-8; otherwise ANSI. A Turkish (1254) file is recognised on an English-locale PC. |
| Preamble | Lines before the table (device name, export date, Excel's `sep=`) are skipped. |
| Header | A text row above numeric columns is the header; without one, columns are numbered. |
| Unit row | A row like `[kW]`, `°C` under the header is appended to the column names. |
| Decimal | `12,5` / `12.5` / `1.234,5` by vote over the cells. Undecidable values such as `12,345` are settled by cells like `0,532` or `1234,567`, then by the delimiter (`;` means comma). |
| Date/time | ISO, `25.09.2026`, `09/25/2026` (day/month order from the values), AM/PM, milliseconds. Separate date and time columns are merged; a time-only column rolls over at midnight. |
| Unix time | Epoch columns (seconds or milliseconds) are shown as local time and offered for the X axis, not as series. |
| Fixed width | Columns come from character positions that are blank on every line. Header words wider than their column, text with spaces (`HIGH TEMP`) and packed digit/letter columns (`00123ABC`) are handled; each line is cut at its own blank, so a value wider than the sample is not truncated. |
| Misaligned header | Names separated by two or more spaces are matched to columns in order when the counts agree. |
| Non-data lines | Repeated headers and footers ("Total rows: 200") are not counted as rows. |
| Missing values | Empty, `-`, `NaN`, `N/A`, `#N/A`, `null`: drawn as gaps, never as zero. |

## Building

Visual Studio 2017 or later with "Desktop development with C++".

```
build.bat            release build -> build\RecordPlot.exe
build.bat debug      debug build
build.bat test       detector tests over tests\samples
build.bat clean
```

The files in `tests\samples` are generated by `tests\make_samples.py`, the icon by
`res\make_icon.py` (both use only the Python standard library).

## Not in this version

- Files are read on the UI thread: a 60 MB, one-million-row file freezes the window for
  about a second.
- CSV fields containing line breaks inside quotes are not supported.
- A quoted decimal comma (`"1,5"`) in a comma-separated file is not read.
- The detection result cannot be corrected by hand.
